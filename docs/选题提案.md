# 软工大作业选题提案：实时协同白板与文档编辑系统

## 1. 为什么选择这个选题？

1. **演示效果极佳**：答辩现场两台设备（或两个浏览器窗口）打开同一个网页链接，在一个屏幕上绘制或输入，另一个屏幕**毫秒级实时同步**，并能看到对方的动态鼠标/光标，答辩冲击力极强。
2. **逻辑确定，零成本**：不依赖任何昂贵且不稳定的 LLM (大模型) API，所有逻辑均基于确定的数据结构与网络同步算法，测试与验收极其稳定。
3. **软工非功能需求（NFR）天然可量化**：非常容易撰写网络同步延迟、并发房间数、网络断开重连恢复（Offline Sync）、帧率（FPS）等高分软工指标。
4. **全栈 B/S 架构**：符合现代软件工程主流的“前后端分离”范式，既包含丰富的前端交互，又包含硬核的后端长连接与数据持久化逻辑。

## 2. 核心架构与功能模块拆分

```
┌─────────────────────────────────────────────────────────────┐
│                     Web 前端 (React/Vue)                    │
│   ┌───────────────────────┐   ┌─────────────────────────┐   │

│   └───────────┬───────────┘   └────────────┬────────────┘   │
└───────────────┼────────────────────────────┼────────────────┘
                │     WebSocket 双向长连接   │
┌───────────────▼────────────────────────────▼────────────────┐
│                 后端 Gateway (Node / Go / Java)             │
│   ┌───────────────────────┐   ┌─────────────────────────┐   │
│   │  房间管理与鉴权 Auth  │   │ 广播与 Pub/Sub (Redis)  │   │
│   └───────────┬───────────┘   └────────────┬────────────┘   │
└───────────────┼────────────────────────────┼────────────────┘
                │                            │
┌───────────────▼──────────────┐ ┌───────────▼──────────────┐
│   协同冲突解决 (CRDT / Yjs)  │ │ 文档/快照数据库 MongoDB  │
└──────────────────────────────┘ └──────────────────────────┘
```


### 功能模块列表：
1. **实时协同绘制/编辑模块（Core Editor/Canvas）**：
   * 支持基础图形（矩形、箭头、手绘线段、文本框）绘制、移动、缩放与图层管理。
2. **数据一致性与冲突解决引擎（CRDT Engine）**：
   * 基于无冲突复制数据类型（CRDT）算法（使用成熟的 `Yjs` 库），解决多用户同时编辑时的冲突，实现状态最终一致性。
3. **协同感知与状态广播子系统（Presence & Awareness）**：
   * 显示当前在线用户列表，并在画布上**实时平滑同步多用户的鼠标轨迹**与选中状态。
4. **房间与权限管理（Room & Access Control）**：
   * 包含房间新建、重命名，基于 URL/房间号快速加入，并提供只读（Viewer）与编辑（Editor）权限区分。
5. **持久化与历史快照（Persist & Version Control）**：
   * 后端定时生成白板/文档矢量数据快照，存储至数据库（MongoDB/PostgreSQL），支持查看历史版本并一键恢复。

## 3. 需求分析指标参考

* **同步延迟（Performance）**：端到端编辑操作同步延迟 **P99 < 100ms**（局域网/同地域条件）。
* **并发能力（Scalability）**：单个协同房间支持 **> 30 人** 同时在线，且广播帧率 **> 50 FPS** 无明显卡顿。
* **最终一致性（Reliability）**：网络断开并重连（Network Flapping）后，系统可在 **200ms 内** 自动补发 Update 差异包并恢复一致。
* **数据安全（Safety）**：异常关闭页面时，通过本地 IndexedDB/LocalStorage 暂存，丢失的操作记录不超过 **1 秒**。
