# 阶段四本轮开发总结

更新日期：2026-10-20。

本轮在已提交的 C1/C2/C3 基础上，完成 Markdown 主页、数据接口和基础编辑流程。本次提交包含此前尚未提交的 C4/C5、A1/A2/A3、B1/B2/B3，以及自动保存所需的正文接口与分析辅助逻辑。

## 已实现的功能

| 范围 | 交付内容 |
|---|---|
| C4/C5：主页及模板 | 与 Docs 主页共用视觉和公共组件；5 类 7 个模板；创建、列表、标题筛选、删除、加载/错误/空状态及手机布局 |
| A1：数据基础 | Markdown 数据字段、客户端类型、4 个幂等索引、可选幂等迁移脚本；旧数据按 rich 兼容 |
| A2/A3：文档接口 | 创建时保存完整源码、标签和 revision；列表按类型过滤；元数据返回类型/标签/修订号；Markdown 仅本人可访问 |
| B1：源码输入 | CodeMirror 6、语法高亮、行号、撤销、搜索、只读配置和中文组合输入处理 |
| B2：编辑会话 | 800ms 自动保存、手动保存、300ms 草稿写入节流、离线恢复、离开/后台保存和修订冲突选择 |
| B3：实时预览 | GFM 标题/列表/表格/任务/代码、双链、80ms 预览防抖、安全链接及原始 HTML 禁用 |
| 编辑所需后端支持 | 正文 GET/PUT、原子 revision 更新及 409 冲突、保存时文本/双链分析与当前用户范围内目标解析 |

当前已打通：**选择模板 → 创建文档 → 输入源码 → 查看预览 → 自动保存 → 刷新继续编辑**。Docs 和 Markdown 分别展示自身类型的文档；富文本原有共享与 Yjs 行为保留，Markdown P0 不开放分享、评论、快照或 Yjs 协作。

本地草稿按用户和文档隔离；冲突时暂停自动保存，由用户选择加载最新版本或保留自己的源码。大正文离开页面时保留草稿，避免依赖超出浏览器 keepalive 限制的请求。

## 使用方式

客户端新增依赖已写入 package.json 和 package-lock.json。其他成员同步本次代码后，在 client 目录执行 `npm ci` 安装锁定依赖；MongoDB 可用后，分别在 server 和 client 目录执行 `npm run dev`。

登录后通过 `☰ → Markdown` 打开主页，新建或打开文档；停止输入约 800ms 后观察 Saved，再刷新检查内容。也可使用 Save now 或 Ctrl/Cmd+S。`VITE_MARKDOWN_API_ENABLED` 默认开启，若已有客户端环境文件显式设置 false，需要改为 true 并重启前端。

索引在后端连接数据库时自动确保，无需先迁移旧文档。本轮仅提供可选迁移命令，没有对开发库执行迁移。
